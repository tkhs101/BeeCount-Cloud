## 结论:是对的,实测通过

东京 `2026-10-20T18:00:00+09:00` 推上去 → 落库 `2026-10-20 09:00:00`(UTC)。
naive `2026-10-21T07:00:00` → 落库 `07:00`(按 UTC 解释)。

变异验证:把归一拿掉(重现第 7 轮那个 bug)→ **变红**。

## ⚠️ 断言放在数据库层,原因值得记

pytest 的 `conftest.py` 有 `ALLOW_APP_RW_SCOPES=false` —— app scope 的
REST 写**默认关闭**,所以这条测试里**没法用 REST 建账本**(403),而账本
只能由 push 物化,读端按账本筛选时对不上。

要验的是「经过 push 之后落库的时间戳对不对」,数据库才是权威处。读端那
一环探针单独验过(带/不带 ledger_id 参数各读到 1 条)。为验一个时间戳把
setup 搞成这样不值得。

## ⚠️ 又一种「单跑绿、全量红」—— 第三种

单跑 9 passed、全量 2 failed。根因:`src.database` 的 engine 是**模块级
全局**,在 `src.main` 第一次被 import 时就建好;而 pytest 按文件名顺序收集,
`test_smoke_real_app.py` 字母序靠后 —— 我模块顶层设的 `DATABASE_URL`
**根本没生效**(早被别的测试 import 过)。

本会话已知三种:模块级 env 污染、模块级单例、**模块级全局 engine**。
根治办法是**别依赖全局状态**:自建 engine + `dependency_overrides[get_db]`
注回去,import 顺序就无关了。

## 附带查清的两个 scope 事实

- `/sync/push` 要 **app scope** —— `client_type="web"` 注册的 token 直接 403
- app token **不能**走 REST 写路径(在 pytest 里),但 `require_scopes` 判的是
  scope 不是 client_type,是 `ALLOW_APP_RW_SCOPES` 关掉了 app scope 的写
