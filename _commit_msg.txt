test(frontend): 变异审计抓出 5 条假护栏,改成真跑 —— 45% 是假的

## 起因

上一轮我写了个假护栏(照抄交易侧判据,结果账户侧根本不成立),
只有做变异测试才发现。于是这轮反问:**我之前写的护栏里还有多少是假的?**

写了审计脚本,对本会话我加的每条前端护栏做一次定向变异,看有没有任何
测试变红。结果:

```
[未检出] 本期应还:statementOut 恒返回 null(功能整个失效)
[未检出] 本期应还:去掉账期守卫(非信用卡也显示)
[未检出] 拆分腿:去掉「不在当前筛选内」标注
[未检出] 导入预览:去掉 splits 列表头
[未检出] 导入预览:hasSplits 恒假(列永远不出现)
```

**11 个变异,5 个没被检出 —— 45% 的护栏是假的。**

## 失败模式完全一致

我所有的前端护栏都是「字符串存在性」检查:

```ts
expect(src).toContain('function statementOut(')   // 代码被写下来了
expect(src).toMatch(/import\.preview\.col\.splits/)  // 字符串在文件里
```

这证明不了「代码被执行到了」。这与 CLAUDE.md 记的「hook 插进函数体,
语法合法但永不可达」是**同一类问题**,只是这次发生在**测试断言**里。

`hasSplits = false` 让整列永远不出现、护栏全绿 —— 比没有护栏更糟,
因为它让人以为这里有保护。

## 我一直以为前端只能做源码正则 —— 那是假设,不是限制

没有 jsdom / @testing-library/react,所以本会话所有前端护栏都是
**读源码文本**。但 vitest **能直接 import 模块**(`aiConfigMerge.test.ts`
早就在这么做了),而这三处逻辑都是**纯函数,无 React / 无 DOM**:

| 抽出 | 位置 |
|---|---|
| `statementOut` | 从组件内提到模块级并 export |
| `previewColumns` | 从组件内提到模块级并 export |
| `legOptions` | 移到 `features/splitLegOptions.ts` |

新增 **24 条真行为测试**,覆盖之前正则够不到的东西:
非信用卡返回 null / 三缺一返回 null / 欠款 0 也返回(已还清是有效状态) /
恰好 2 条腿就要出现拆分列 / 候选为空时也要把腿的账户放进去 /
不改原数组(React state 被就地修改)。
