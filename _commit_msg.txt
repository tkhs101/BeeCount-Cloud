test: 前后端字段名契约护栏 —— 后端改名会静默少一块 UI

## 为什么不可省

前端大量派生函数是「字段缺失就**静默**返回 null / 不渲染」:
`statementOut` 缺 `statement_bill` 就不显示那一格、`previewColumns`
缺 `splits` 就不出现那列。

而 **TypeScript 类型是手写的**,它不会验证运行时真的返回了这些字段。
所以「后端改名 -> 前端读不到 -> UI 静默少一块」这条路上:`tsc` 不报错、
`vitest` 全绿、用户只看到「这个功能怎么不见了」。

## 做法

真跑一次 API 拿响应 key,再用正则从 `types.ts` 读出声明的字段名,
取**「前端声明但后端不返回」**的差集。这条测试因此同时依赖**真服务**
和**前端源码** —— 任何一侧改名都会红。

只查一个方向:后端多返回的字段不算问题(前端可以先不声明)。

实测当前状态:前端声明 23 个字段,后端全部返回;后端多返回的 4 个
(`balance` / `income_total` / `expense_total` / `tx_count`)是
`AccountWithStats` 的统计字段,前端另有类型 —— 契约是干净的。

## 正则本身也要有下限

`assert len(declared) > 15` —— 正则失效时不能静默通过
(与 CLAUDE.md 里「tokenize 恒真」同一类)。

## 变异验证

| 变异 | 结果 |
|---|---|
| 后端把 `statement_bill` 改名 | 变红 |
| 后端漏掉 `statement_bill`(只加进 schema) | 变红 |
